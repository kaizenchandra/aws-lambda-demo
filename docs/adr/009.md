# ADR-009 — Immutable receipts before completion

## Context

S3 and DynamoDB cannot participate in a common transaction.

## Decision

Deterministic key/content; conditional If-None-Match write; compare SHA-256 metadata on existing object; commit
completion only after receipt success.

## Alternatives Considered

Overwrite on every retry; complete before receipt; permanent in-memory lock.

## Consequences

Crashes can leave a recoverable receipt and PENDING aggregate. Worker has no delete permission. A different receipt
under the same key is a conflict.
